# Rust Workspace & Crates Deep-Dive

The LibraX core engine is implemented in **Rust (2024 edition, 1.85+)** as a modular 17-member workspace. This separation of concerns enforces clean boundaries, deterministic performance, and isolated unit/integration testability.

```
crates/
├── librax-types/         # Common domain primitives and data transfer objects
├── librax-config/        # Configuration loader (YAML, ENV, CLI flags)
├── librax-connectors/    # Multi-source log connector definitions & health checks
├── librax-normalizer/    # Multi-vendor raw log parsers and schema normalization
├── librax-enrichment/    # GeoIP, ASN, Threat Intel feeds & IOC verdict engine
├── librax-detection/     # Stateful/stateless detectors & MITRE ATT&CK engine
├── librax-entities/      # Entity resolution, identity mesh & asset inventory
├── librax-correlation/   # Sliding window correlator & multi-factor link scoring
├── librax-graph/         # Petgraph-backed DAG, blast radius & attack chain paths
├── librax-mitre/         # MITRE ATT&CK Enterprise matrix & tactic progression
├── librax-risk/          # Multi-dimensional risk & patient safety impact scoring
├── librax-incidents/     # Incident state machine, lifecycle & builder
├── librax-response/      # Containment engine, safe simulation & approval gates
├── librax-storage/       # In-memory and persistent thread-safe storage
└── librax-ai/            # Deterministic briefing generator & assertion provenance
services/
├── librax-api/           # Axum 0.8 HTTP REST API & WebSocket server
└── librax-simulator/     # Multi-tempo adversary attack replay engine
```

## Workspace Members Breakdown

### 1. `librax-types`
- **Purpose:** Foundation crate containing shared domain models.
- **Key Structs:**
  - `RawEvent`: Unparsed telemetry log with source identifier and payload string/JSON.
  - `NormalizedEvent`: Strongly-typed event with canonical timestamp, host, user, network sockets, hashes, and message.
  - `SecuritySignal`: An alert generated by a detector, including severity, MITRE tags, and cited evidence events.
  - `Incident`: An aggregated security incident containing correlated signals, entities, graph, risk scores, and AI briefings.
  - `EntityRef`: Canonical entity reference (`Host`, `User`, `Ip`, `File`, `Process`, `Hospital`).
  - `ResponseAction`: Containment action specification (`IsolateHost`, `DisableAccount`, `BlockIp`).

### 2. `librax-normalizer`
- **Purpose:** Ingests unformatted raw events and transforms them into standard schema.
- **Supported Sources:**
  - `active_directory` / `samba`: Windows Security Event IDs (4624, 4625, 4672, 4768, 4769, 4776, 5140, 5145) and Samba JSON/full_audit formats.
  - `edr`: Process creation, injection, DLL loads, and script blocks.
  - `firewall`: Connection drops, port scans, and egress flows.
  - `pacs`: DICOM medical imaging queries, storage transfers, and modality commands.
  - `pam` / `vpn`: Privilege elevation and remote access authentication.

### 3. `librax-detection`
- **Purpose:** Evaluates rules against incoming normalized events.
- **Key Features:**
  - `Detector` Trait: Common interface `fn evaluate(&mut self, event: &NormalizedEvent) -> Vec<SecuritySignal>`.
  - Stateful detection: In-memory sliding windows with automatic TTL expiration.
  - Directory heuristics: Special detectors tailored for Active Directory attack chains (Kerberoasting, AS-REP roasting, DCSync, Password Spraying).

### 4. `librax-entities`
- **Purpose:** Disambiguates disparate identifiers across systems into canonical entities.
- **Resolution Capabilities:**
  - Resolves NetBIOS names, FQDNs, and IP addresses to canonical host records.
  - Correlates SAMAccountNames, UPNs, and Kerberos principal names to unified user identities.
  - Maintains critical healthcare asset registry (Domain Controllers, EHR Servers, CT/MRI modalities).

### 5. `librax-correlation`
- **Purpose:** Correlates independent signals into coherent attack chains.
- **Algorithm:**
  - Maintains active temporal clusters within a configurable sliding window.
  - Evaluates multi-factor link contributions:
    $$\text{Score} = w_{\text{id}} \cdot F_{\text{id}} + w_{\text{host}} \cdot F_{\text{host}} + w_{\text{net}} \cdot F_{\text{net}} + w_{\text{ev}} \cdot F_{\text{ev}} + w_{\text{stage}} \cdot F_{\text{stage}}$$
  - Requires at least one **substantive** factor (temporal proximity alone never links).

### 6. `librax-graph`
- **Purpose:** Constructs the structural incident graph and computes graph metrics.
- **Key Features:**
  - Backed by `petgraph::graph::DiGraph`.
  - Computes blast radius, attack entry points, and shortest lateral movement paths.
  - Serializes graph nodes and edges for the React SVG HUD.

### 7. `librax-risk`
- **Purpose:** Calculates objective risk ratings ($0–100$) based on threat confidence, critical asset exposure, and blast radius.
- **Formula:**
  $$\text{Risk} = \min\left(100, \left(\text{BaseSeverity} \times \text{AssetWeight} \times \text{BlastMultiplier}\right) + \text{TemporalBonus}\right)$$

### 8. `librax-ai`
- **Purpose:** Generates analyst briefings with zero hallucinations.
- **Guarantees:**
  - Strict assertion provenance: Every statement is labeled as `Fact` or `Inference`.
  - Direct citations: Every claim contains pointers to the exact `event_id` values supporting it.

### 9. `librax-response`
- **Purpose:** Proposes and simulates automated containment playbooks.
- **Safety Features:**
  - Non-destructive by default: Simulates actions and predicts operational side-effects.
  - Approval Enforcement: High-impact actions require a named analyst signature.

### 10. `services/librax-api`
- **Purpose:** Primary HTTP REST and WebSocket gateway powered by `Axum 0.8`.
- **Endpoints:**
  - `/api/v1/dashboard`: High-level metrics, reduction funnel, and top active incident.
  - `/api/v1/incidents`: Incident listing, graph queries, and detail views.
  - `/api/v1/events`: High-speed raw telemetry search and filtering.
  - `/api/v1/sources`: Telemetry ingestion pipeline status and health metrics.
  - `/api/v1/attacks`: Attack range catalog and campaign execution controls.
  - `/api/v1/intel`: Indicator of Compromise (IOC) lookup and feed explorer.

### 11. `services/librax-simulator`
- **Purpose:** Replays full-spectrum adversary campaigns against the engine at controllable playback rates ($10\times, 20\times, 60\times, \text{Burst}$).
